# `version/1.20.1` 独立双线设计

## 结论

可以实现。建议把 `D:\apps\appss\fl\HMCL\mod\ExposureCamcorder\version\1.20.1` 做成**独立 Gradle 工程根**，与当前 1.21.1 主线并行维护。

## 目标

- 保留现有 1.21.1 工程不变。
- 新增 1.20.1 版本线，支持 Fabric 与 Forge。
- 后续修改能同步到两条线，但每条线各自编译、各自打包。

## 设计原则

- 同仓库，双工程根。
- 版本敏感逻辑分离。
- 共享素材和文案可同步，编译代码不强行共用。
- 1.20.1 线按旧版 API 约束实现，不反向污染 1.21.1。

## 推荐结构

```text
ExposureCamcorder/
  common/
  fabric/
  neoforge/
  version/
    1.20.1/
      common/
      fabric/
      forge/
      gradle.properties
      settings.gradle
      build.gradle
```

## 版本边界

- 1.21.1 继续使用当前根目录构建。
- 1.20.1 线使用自己的 Minecraft、Loader、Forge、Fabric 依赖。
- 1.20.1 不能直接依赖 1.21.1 的数据组件、NeoForge 入口或新版本网络类型。
- 1.20.1 的物品状态与网络协议需要按旧版机制单独适配。

## 维护方式

- 共享的图片、语言、说明文案可在两条线之间同步。
- 代码修改按版本分别落地。
- 后续如果要“同时修改两条线”，应先改公共设计，再分别提交到两个工程根。

## 风险

- 1.20.1 对应的依赖版本必须可用，否则工程无法完整落地。
- 两套工程会带来重复维护成本。
- 如果共享素材不同步，两个版本的体验会分叉。

## 建议

采用“**1.21.1 主线 + `version/1.20.1` 独立分支线**”的方式最稳，后续维护成本最低，也最适合长期并行更新。
