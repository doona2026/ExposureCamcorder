# Forge 47.x + Fabric 1.20.1 双线设计

## 结论

可以实现，但应按“并行两条主版本线”来做：保留当前 1.21.1 结构，同时新增一条 1.20.1 + Forge 47.x + Fabric 1.20.1 适配线。

## 约束

- 1.20.1 不能直接复用当前 1.21.1 里依赖数据组件的实现。
- 不能把同一份 common 代码无差别同时编译给 1.20.1 和 1.21.1。
- Fabric API 以本地路径 `D:\apps\appss\fl\HMCL\mod\fabric-api-1.20.1` 接入。

## 方案

1. 保留现有 1.21.1 工程结构不动。
2. 新增 1.20.1 平台模块，分别承载 Forge 47.x 和 Fabric 1.20.1 入口。
3. 将版本敏感逻辑下沉到少量桥接层，重点覆盖注册、网络、物品持久化和平台事件。
4. 1.20.1 线使用 NBT / Forge 侧等价机制替代 1.21.1 的数据组件存储。

## 需要验证的点

- Forge 47.x 目标版本与当前依赖链是否一致。
- 本地 Fabric API 路径是否能以仓库或本地发布方式被 Gradle 正确解析。
- 当前公共逻辑里有哪些类必须拆分为 1.20.1 / 1.21.1 双实现。

## 推荐执行顺序

1. 先补 1.20.1 目标的 Gradle 与模块骨架。
2. 再拆版本敏感 API。
3. 最后回填 Forge / Fabric 1.20.1 的入口和资源。
